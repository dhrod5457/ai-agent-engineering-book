# Memory / Identity / Sandbox / Policy Freshness Audit

기준일: 2026-10-02

## Memory security

Microsoft:
https://www.microsoft.com/en-us/security/blog/2026/06/22/guarding-ai-memory/

관련 preprints:
- https://arxiv.org/abs/2606.04329
- https://arxiv.org/abs/2607.14651
- https://arxiv.org/abs/2607.27080

확인:
- persistent memory poisoning을 단발성 prompt injection과 별도로 다룰 근거가 있음
- compositional multi-record attack과 dormant/context-triggered attack이 보고됨
- write-time defense만으로 모든 공격 유형을 충분히 막는다고 볼 수 없음
- repair / forget lifecycle을 별도 평가하는 연구가 등장

주의:
각 preprint의 benchmark 수치와 세부 taxonomy는 출간 직전 재검증한다.

## Microsoft Entra Agent ID

Sources:
- https://learn.microsoft.com/en-us/entra/agent-id/agent-identities
- https://learn.microsoft.com/en-us/entra/agent-id/autonomous-agent-authentication-authorization-flow

확인:
- agent identity를 special service principal로 표현
- agent identity 자체는 credential을 직접 보유하지 않고 blueprint가 token 획득
- delegated/interactive와 autonomous access를 구분

주의:
이는 Microsoft Entra의 identity model이며 업계 전체 표준 taxonomy가 아니다.

## AWS risk-tiered human approval

Source:
https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentsec04-bp02.html

확인:
- 모든 action을 human review로 보내는 것은 reviewer fatigue / rubber-stamp approval을 만들 수 있음
- risk-tiered approval 권고
- risk classifier의 authoritative signal은 deterministic logic을 사용
- reviewer에게 충분한 decision context 제공
- timeout / escalation / audit 필요

본문의 R0~R4는 AWS taxonomy가 아니라 이 책의 illustrative control profile이다.
